# Data Quality Report — Online Retail II (2009-2010)

## Огляд датасету

Транзакційні дані британського онлайн-магазину за 2009-2010 рік.

- **Кількість рядків:** 525 462
- **Кількість колонок:** 8

| Колонка | Назва | Опис |
|---|---|---|
| A | InvoiceNo | Номер рахунку-фактури |
| B | StockCode | Код товару |
| C | Description | Опис товару |
| D | Quantity | Кількість |
| E | InvoiceDate | Дата і час замовлення (dd.mm.yyyy hh:mm) |
| F | UnitPrice | Ціна за одиницю |
| G | CustomerID | ID клієнта |
| H | Country | Країна |

## Перевірені проблеми якості даних

| Column | Problem | Count | % від усіх записів | Action |
|---|---|---|---|---|
| CustomerID | Пропуски | 107 927 | 20.5% | Позначити як Guest / не видаляти рядок — транзакція все одно валідна для аналізу продажів |
| Description | Пропуски | 2 928 | 0.6% | Investigate вручну, можливо технічні позиції без опису |
| InvoiceNo + StockCode | Дублікати | 25 401 | 4.8% | Потребує додаткової перевірки: помилка вводу чи легітимний повторний рядок для того самого товару в замовленні |
| UnitPrice | Сума 0 або менше 0 | 3 691 | 0.7% | Таких даних небагато, варто перевірити чи це втрати підприємства чи помилки оператора |
| Quantity | 0 або менше 0 | 12 327 | 2.3% | Більшість — це повернення (пов'язані зі скасованими операціями), але є випадки не-повернення, що потребує окремої перевірки |
| InvoiceNo (починається з "C") | Задокументовані скасування | 10 207 | 1.9% | Відокремити в окремий прапорець при очищенні, не видаляти |

## Що зроблено на етапі очищення (лист `clean_data`)

На основі знайдених проблем створено новий лист `clean_data` з додатковими колонками:

- **Cancelled** — прапорець, чи є операція скасуванням (InvoiceNo починається з "C")
- **Revenue** — розрахункова сума операції (`Quantity × UnitPrice`)

## Висновок

Дані містять типові для реальних транзакційних систем проблеми: значна частка пропущених CustomerID (~20%), помітна кількість дублікатів пари InvoiceNo+StockCode (~5%) та скасованих операцій (~2%). Жодна проблема не є критичною для видалення рядків повністю — більшість вимагає позначення прапорцями (Cancelled) або окремого розрахунку (Revenue), а не видалення даних.
